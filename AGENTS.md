## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.

Package manager is **npm** (not yarn/pnpm) — use `npm run dev`, `npm run build`, `npm run preview`, `npm run lint`, `npm run format`.

`typescript` is pinned to `6.0.3` in devDependencies: `typescript-eslint`/`@typescript-eslint/parser` don't yet support TypeScript 7's native compiler. Don't bump `typescript` past 6.x without confirming typescript-eslint support first, or `npm run lint` will crash.

## Content Collections

- Blog posts live in `src/content/blog/*.md`, defined by the `blog` collection in `src/content.config.ts` using the Content Layer API (`glob()` loader + Zod `schema`).
- Import `z` from `astro/zod`, not `astro:content` — that re-export is deprecated as of Astro 6.
- Schema fields: `title`, `description`, `pubDate` (coerced date), optional `updatedDate`, optional `draft`. Draft posts must stay filtered out of `getCollection('blog', ...)` calls in `src/pages/blog/index.astro` and `src/pages/blog/[...slug].astro`.
- Code fence language identifiers must be valid Shiki grammar names (e.g. `apache`, not `apacheconf`), and must not use `lang:filename` annotations — Shiki doesn't support that syntax and silently falls back to plaintext.

## Design System

- Theme tokens (`--color-canvas`, `--color-ink`, `--color-muted`, `--color-line`) are defined in `src/styles/global.css`'s `@theme` block (light values) and re-defined inside a `.dark { … }` block (dark values) — every utility built from them (`bg-canvas`, `text-ink`, `text-muted`, `border-line`) flips automatically. `border-line` is deliberately low-opacity (~0.14) for the barely-visible dotted section borders.
- Dark mode is a **manual toggle**, not just `prefers-color-scheme`: `@custom-variant dark (&:where(.dark, .dark *));` in `global.css` makes Tailwind's `dark:` variant class-based. `BaseLayout.astro` has a no-flash `is:inline` script in `<head>` that sets the `dark` class from `localStorage.theme`, falling back to system preference. `ThemeToggle.astro` flips the class and persists the choice.
- Fonts are self-hosted via `@fontsource-variable/*` (imported at the top of `global.css`, family names are `"<Name> Variable"`): `font-display` = Space Grotesk (headings, nav/footer labels), `font-sans` = Inter (body text), `font-mono` = JetBrains Mono (code, timestamps).
- `BaseLayout`'s `<main>` is intentionally generic/full-bleed (`flex flex-1 flex-col`) — pages opt into a constrained width themselves rather than `BaseLayout` imposing one. `BlogPostLayout.astro` has a full-bleed title section (dotted bottom border) followed by a full-bleed `px-6 py-12 md:py-16` wrapper whose _inner_ `<article>` carries `mx-auto w-full max-w-2xl`, for a readable line length. The home page and blog index are both full-bleed edge-to-edge throughout, matching the header/footer.
- Width-constrained-section gotcha: padding must be applied to the full-width outer element _before_ an inner `mx-auto max-w-2xl` box centers itself — never put the horizontal padding on the already-centered box itself. Padding-then-center and center-then-padding compute different left offsets on wide viewports (the difference is exactly the padding value), which once caused the blog post's title box and article body to visibly misalign. Every width-constrained section on this site (title boxes, `BlogPostLayout`'s article wrapper) follows the "pad the outer element, center a bare `max-w-2xl` box with no padding of its own inside it" pattern — match it exactly for any new section.
- Tailwind's preflight sets `cursor: default` on `<button>` — add `cursor-pointer` explicitly on any clickable button (see `ThemeToggle.astro`).
- Stacking gotcha: an `absolute`-positioned element always paints above `static` in-flow siblings regardless of DOM order. To put decorative absolutely-positioned content (e.g. a title box's dot field) _behind_ real content, the real content needs its own `relative` (or other positioned) wrapper — see the `relative z-10` wrapper in `src/pages/index.astro` or `BlogPostLayout.astro`.
- `src/lib/grains.ts` exports `phyllotaxis()`, a golden-angle point scatterer used for the site's decorative dot fields. The home hero uses it for two depth layers driven by a parallax script (`.parallax-layer` + `data-depth`, see `src/pages/index.astro`); other title boxes (blog index, blog post) use a single static layer with no script at all. Default to the static version unless a page specifically calls for the parallax motion.
- The hero's parallax listens to both `pointermove` and `pointerdown` (shared `applyParallax(x, y)` helper) — `pointermove` alone only drives continuous movement on mouse hover or an active touch-drag, so `pointerdown` is what makes a plain mobile tap shift the dots at all, since a tap with no drag never fires `pointermove`. Deliberately not gyroscope-based: `DeviceOrientationEvent` requires an explicit `requestPermission()` call behind a user gesture on iOS Safari (but not Android), which would mean a permission prompt just for a barely-visible decorative effect — rejected as not worth the friction/inconsistency for this.
- **Every full-bleed "title box"** (dotted-bordered section that opens a page — home hero, blog index, blog post) gets the `phyllotaxis()` dot-scatter accent. This was missed once when `BlogPostLayout.astro` was redesigned and had to be added back after the fact — when adding a new title box, add the grains along with it rather than as an afterthought.
- Recurring pattern for a "grid of boxes" (nav, blog post cards): give every cell `border-b border-dotted border-line`, and add the internal column divider with Tailwind's `odd:`/`even:` nth-child variants (e.g. `odd:sm:border-r` for a 2-column grid) rather than a wrapping border — this avoids doubled-up lines between adjacent boxes. See the blog post grid in `src/pages/blog/index.astro`.
- Long-form content (rendered Markdown via `<Content />`/`<slot />`) must be wrapped in `class="prose"` — Tailwind's preflight zeroes out margin/padding on every element, so without `@tailwindcss/typography` (`@plugin "@tailwindcss/typography";` in `global.css`) prose content renders with no paragraph spacing, no list markers, nothing. The plugin's `--tw-prose-*` color variables are remapped to the site's theme tokens directly in `global.css` (not via a JS config), so `prose` content follows light/dark automatically without `prose-invert`. Use the `prose-headings:font-display prose-code:font-mono` modifiers to keep it on-brand; the `<article>` itself carries `mx-auto w-full max-w-2xl` (not `max-w-none`) per the width-constrained-section pattern above. See `BlogPostLayout.astro`.
- Two title-box variants, pick by page role: **top-level pages** (Blog index, About) use the centered treatment — `text-center`, uppercase `h1`, symmetric `py-16 sm:py-20 md:py-24` (see `src/pages/blog/index.astro`, `src/pages/about.astro`, which are near-identical). **Detail pages** (an individual blog post) use the left-aligned treatment with a `← Blog` back-link above the title (see `BlogPostLayout.astro`). Both variants still get the `phyllotaxis()` grains per the rule above.
- Don't publish personal contact info (email, phone, etc.) on the site unless the user explicitly gives that exact value for that purpose — e.g. the About page's `mailto:` link uses `mail@aswink.in` because the user gave it directly, not the personal Gmail address known from this environment's context.
- `Nav.astro` is responsive with two independent right-side layouts, not one: below `md:`, the links box and theme-toggle box (`hidden md:flex`) are replaced by a single hamburger button (`md:hidden`) that expands a full-width collapsible panel; at `md:` and up the original always-visible links+toggle boxes are used and the panel/button never render. Add new top-level page links to **both** the desktop links box and the mobile panel (see the shared `links` array in `Nav.astro`) — they're separate markup blocks by necessity (very different layout), not one list reused via CSS.
- The mobile menu's expand/collapse is pure CSS via the `.mobile-menu` class (`global.css`): `grid-template-rows: 0fr` → `.is-open { grid-template-rows: 1fr }`, toggled by a small script that also flips `aria-expanded` and swaps the hamburger/close icons. Gotcha: any border on the _collapsing_ element itself still renders at 1px even when its content is squeezed to ~0 height — put dividers (like the panel's top border) on the inner content that gets `overflow: hidden`-clipped, not on the outer `.mobile-menu` container, or you get a permanent stray line when the menu is closed.
- Divider borders between adjacent boxes should be scoped to the breakpoint(s) where both boxes are actually visible — e.g. the nav title box's divider is `md:border-r` (not a bare `border-r`) because on mobile the next element is the hamburger button, and that pairing intentionally has no divider or box around it (tried boxing the hamburger button in a bordered square; reverted — the user preferred it as a plain borderless icon, matching the desktop theme-toggle's treatment).
- Components rendered more than once on the same page (e.g. `ThemeToggle.astro`, once in the desktop toggle box and once in the mobile panel) must not target a hardcoded `id` in their script — Astro dedupes identical component `<script>`s to run once, so an `getElementById` lookup only ever finds the first instance and the second one's handler silently never attaches. Use a shared class and `querySelectorAll(...).forEach(...)` instead. `ThemeToggle` also takes an optional `showLabel` prop to add a text label in spacious contexts (mobile panel) while staying icon-only in compact ones (desktop box).
- Mobile font-size safety: don't jump straight to a large base size (e.g. `text-7xl`) on an element that can hold a single unbreakable word (like the hero's cycling word) — it can overflow a narrow viewport since there's no space to wrap at. Start from a smaller mobile-first size and scale up gradually across more breakpoints (the hero uses `text-5xl sm:text-6xl md:text-7xl lg:text-8xl xl:text-9xl`). Multi-word headings (post titles, nav title) wrap naturally and don't need this.
- The viewport meta tag in `BaseLayout.astro` must include `initial-scale=1` (`width=device-width, initial-scale=1`) — without it some mobile browsers can apply unexpected zoom/layout behavior.
- `Footer.astro` is deliberately quieter than `Nav.astro`: lowercase `font-mono` (no `uppercase`/`tracking-wide`) instead of the nav's bold uppercase `font-display`, on the theory that a loud header + quiet footer reads better than matching caps in both, especially now that the footer holds three items (copyright, GitHub, email) instead of one. Icon-only links (GitHub uses a filled brand-mark path, email a stroke-based envelope matching `ThemeToggle`'s line-icon style) need `aria-label` on the `<a>` and `aria-hidden="true"` on the `<svg>`, since the icon alone gives the link no accessible name.
- To make a row of boxes span full-width with no dead gap (footer: copyright + GitHub + email), give the first box `flex-1` so it consumes all remaining space rather than using `justify-between` (which leaves genuine empty canvas between groups). Its content stays left-aligned on its own since flex children default to `justify-content: normal` on their own axis. This matters for borders too: boxes that are truly adjacent (via `flex-1`, no gap) need exactly one shared divider between them (avoid doubling, per the grid-of-boxes rule above) — but a box-group that sits across a real `justify-between` gap from its neighbor (like `Nav.astro`'s right-side group) needs its own opening border (e.g. `border-l` on the group) to read as bounded, since there's nothing physically adjacent to borrow an edge from.

## Hosting

- Hosted on Firebase Hosting, project `aswin-website` (`.firebaserc` pins this as the default project). Live URL: `https://aswin-website.web.app`.
- `firebase.json` sets `public: "dist"` — Astro's default static build output. No rewrites/SPA fallback needed since every route is a real static file (`astro build` emits `path/index.html` per page); Firebase Hosting serves those automatically for both `/path` (301 → `/path/`) and `/path/` requests.
- Deploy with `npm run deploy` (runs `astro build` then `firebase deploy --only hosting`). Requires being logged in via `firebase login` (CLI: `firebase-tools`, installed globally, not a project devDependency).
- `astro.config.mjs`'s `site: "https://aswink.in"` anticipates the custom domain but it is **not yet connected** — DNS for `aswink.in` has not been pointed at Firebase Hosting. Until that's done, the canonical live URL is the `.web.app` one above.
- `.firebase/` (local deploy cache) and `firebase-debug.log` are gitignored.
